THE TOOLKIT

Small details.
Stronger communities.

Enable the protections you need. Every setting belongs to your server and is saved across restarts.

Message protection

Anti-spam uses a configurable message threshold and a 60-second timeout. Anti-link filters links and invites. Word, domain, and user blacklists work independently.

Administrators are exempt from message filters. Edited messages are checked too. Domain blocks include subdomains.

Raid response

Rapid joins trigger an @everyone text-channel lockdown. Staff can restore the previous overwrite settings with /lockdown enabled:false.

Explicit role permissions may override the lockdown. It does not stop people joining or restrict voice channels.

Anti-nuke & webhooks

Three audited channel deletions, role deletions, or bans by one actor in 10 seconds trigger removal of editable roles with dangerous permissions.

Webhook protection removes newly created webhooks from untrusted actors. Audit attribution and role order limit what the bot can do; deleted content cannot be prevented or recovered automatically.

Account review

Set a minimum account age to kick new accounts below your threshold. Anti-alt flags young accounts without custom avatars for human review.

Discord does not expose the information needed to prove that two accounts belong to one person.

Moderation & cases

Ban, kick, warn, timeout, untimeout, unban, and purge. Actions check staff permissions and role hierarchy. Warnings are recorded even if a member’s DMs are closed.

Send case notifications to a staff log channel and view the latest cases with /cases.

Private support tickets

Configure a staff role and category, then let members open a private support channel. Staff can claim tickets, close access, and export up to 500 recent messages as a text transcript.

Closed channels remain available to staff until manually deleted. Server administrators retain access.

Structure backups

Save roles, channels, and permission overwrites. Download JSON copies or recreate missing objects with a confirmed restore command.

Messages, member assignments, integrations, files, and webhooks are excluded. Existing objects are retained; review role order after restoring.

A FEW STEPS TO A CALMER SERVER

Make yourself
at home.

  1. Create your Discord application

    Open the Discord Developer Portal, create an application, and enable Server Members Intent and Message Content Intent on its Bot page. Keep the bot token private.

  2. Connect the bot

    Copy .env.example to .env in the project root. Set DISCORD_BOT_TOKEN and DISCORD_CLIENT_ID. Use Node.js 24, run npm ci, then npm run deploy to register slash commands and npm start to launch the bot and site.

  3. Invite & arrange permissions

    The operator must configure a public application ID before the invite button can connect.

    Add to Discord ↗

    Move the bot role above members it should moderate. Grant only the permissions required by the enabled tools. Anti-nuke requires View Audit Log and Manage Roles; private tickets require Manage Channels.

  4. Give your bot some direction

    Run /config logs and /config tickets. Enable each filter using /protection. Review /protection status. Protections start disabled so staff can choose the server’s rules.

  5. Keep your records safe

    Use persistent storage for DATA_DIR. Back up the database and download structure snapshots. Run one bot instance per database. The website can also be hosted separately by uploading the website folder to your web host.

All server management happens through Discord slash commands. The public website has no login or dashboard.

YOUR INFORMATION

Privacy,
in plain language.

Ultimate Guardian stores server configuration, blacklist entries, trusted user IDs, ticket metadata, moderation cases, and server structure backups in the operator’s database. Moderation cases include Discord IDs, actions, reasons, and timestamps.

Message processing

Message text is processed to apply enabled filters. The bot does not archive general chat messages in its database. Staff-requested ticket transcripts contain up to 500 recent messages and attachment URLs and are sent privately in Discord. Staff should handle exported transcripts carefully.

Access & deletion

Authorized server staff can view configuration, cases, and backups. The server owner can delete stored server data with /config reset after closing tickets and unlocking the server. The bot deletes its stored records when it receives a server removal event. Offline removals, exported files, hosting backups, Discord’s own data, and staff log messages may require separate deletion by the operator or staff.

The website

The application adds no analytics, advertising cookies, or account system. The hosting provider may process request metadata. Discord and GitHub links are governed by those services’ policies.

Contact

Use the operator’s support channel to request access, correction, or deletion. Do not post tokens or private message content in public issues. Operators should provide their own private contact route before a public launch.

COMMUNITY EXPECTATIONS

Use it
with care.

Ultimate Guardian provides automated Discord moderation and community tools. Server staff choose its configuration and remain responsible for reviewing actions, permissions, exports, and member appeals.

Responsible use

Use the bot only in servers you are authorized to manage. Follow Discord’s terms and community guidelines. Do not use the bot to harass people, collect credentials, or bypass another community’s rules.

Automation has limits

Filters can flag legitimate messages or miss harmful activity. Discord permissions, role hierarchy, audit attribution, API limits, and service availability affect protection. Keep human moderators available and maintain independent backups.

Backups & availability

Structure snapshots do not contain messages, members, files, or complete server state. Restores may be partial and require manual review. Availability is not guaranteed. Operators control hosting, support, and retention.

Support & changes

Report problems through the support channel. Operators should adapt these terms to their service and announce material changes before relying on them for a public launch.

Keep your bot token, API keys, and private server messages out of public support requests.
The bot doesn’t respond to commands

Run npm run deploy, check the application ID matches your token, and confirm the bot is online. Global commands may take time to appear; a test guild can make registration faster.

A protection isn’t taking action

Check /protection status, the bot’s permissions, and role order. Administrators bypass message filters. Audit-based protections need View Audit Log.

The bot loses settings on redeploy

Point DATA_DIR to a persistent disk. A host’s temporary filesystem will not preserve the database across deployments.
